About

    
I'm in my 5th semester of Computer Science at the University of Europe for Applied Sciences in Potsdam. Since August I've been running a self-directed, project-based curriculum in cloud and DevOps engineering — Linux, Git, Docker, AWS, networking, and now Terraform — with one rule: I write every line myself, so I can explain any of it, not just run it.

    
That means the projects below include the real errors I hit along the way — a mistyped flag, a locked-down IAM policy that correctly refused to let me start a server, a port nobody was listening on. I'd rather show the debugging than hide it.

Self-healing AWS infrastructure with Terraform & CI/CD

      
terraform · aws ec2 · auto scaling · ssm · s3 · github actions · oidc

      
Two services on EC2, each in an Auto Scaling Group that replaces failed instances automatically. I terminated a live instance and the ASG activity log shows the replacement being launched (screenshot in the repo).

      
    
        
  • No SSH and no inbound ports: admin access through AWS Systems Manager Session Manager, IMDSv2 required, encrypted volumes
    • 
        
  • Pipeline: format, validate, offline tests and Checkov on every pull request; on main a saved plan is reviewed, approved and then exactly that plan is applied
    • 
        
  • GitHub OIDC instead of stored AWS keys, with separately scoped plan and apply roles
    • 
        
  • State in a versioned, encrypted, private S3 bucket with locking, managed by a separate bootstrap configuration
    • 
      

      github.com/MultiCloudEng/aws-terraform-infrastructure
